## Design

Cairn hosts the lifecycle gate for the stack smoke because it is the final readiness consumer, but the fixture records explicit producers and source repo ownership. The smoke fixture is intentionally small: one Rust crate, one Octet function-address artifact, one Kamacite receipt/projection, one Valence receipt/graph summary, one Mantle binding receipt, and one Cairn readiness receipt.

### Decisions

1. **Fixture is reproducible.** Expected hashes are either regenerated by a documented command or checked against committed outputs.
2. **Adapters are temporary only.** Fixture scripts must use first-class repo commands once the CLI adapter changes land.
3. **Positive and negative live together.** The same fixture directory includes valid and invalid cases.
4. **No semantic claims.** Fixture documentation repeats that a passing smoke proves evidence exchange and readiness policy only.
5. **Repo ownership is explicit.** Each artifact names its producing repo and command so regressions can be triaged to the right layer.

### Validation shape

Positive smoke checks a valid path through all five repos. Negative smoke cases mutate one boundary at a time: function address, source span, Kamacite receipt hash, Valence role, Mantle claim scope, Cairn required missing evidence, and non-claim overclaim text.
