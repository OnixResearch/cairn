# Proposal: Add Preserves corpus update rail

## Summary

Add an explicit operator/developer rail for refreshing the checked-in Preserves canonicalization corpus hashes. The corpus remains an internal deterministic fixture contract; this change only replaces ad-hoc helper-crate regeneration with a first-class Cairn command.

## Motivation

`fixtures/preserves-canonicalization/corpus.json` now catches Preserves encoding/hash drift, but its `expected_hash` fields were initially generated by a temporary ignored helper. Future Preserves dependency bumps should be intentional and reviewable, with a deterministic command that reports stale cases and rewrites only expected hash fields when explicitly requested.

## Scope

- Add a read/dry-run-by-default CLI rail for checking/updating Preserves corpus hashes.
- Require an explicit mutation flag before rewriting the corpus file.
- Preserve corpus `id`, `description`, and `value` material.
- Add focused CLI tests for stale detection, dry-run no-mutation behavior, explicit update behavior, and malformed corpus rejection.
- Keep public receipt schemas and stored agent receipts unchanged.

## Non-goals

- No public replacement of JSON receipt surfaces.
- No new Preserves DTO schema.
- No automatic dependency-bump workflow.
