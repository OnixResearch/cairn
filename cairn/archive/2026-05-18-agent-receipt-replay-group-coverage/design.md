## Context

Cairn now has policy-owned replay groups and agent receipts that carry replay evidence. The `agent` group in `determinism_replay_policy.groups` names the reviewed replay preflight for agent receipt wrappers. However, `agent-receipt validate` still uses a Rust constant for required replay cases and emits only `required_replay_cases`, so a policy edit can drift from the validator until Rust is changed.

## Goals / Non-Goals

**Goals:**
- Make `agent-receipt validate` derive required cases from the policy `agent` replay group.
- Keep validation deterministic when the policy group is missing or malformed.
- Preserve expanded case coverage checks so older wrappers that only record cases remain understandable.
- Allow wrappers to record `replay_selected_groups` and require it to contain `agent` for first-class group evidence.
- Keep receipt fields stable and documented.

**Non-Goals:**
- No new replay cases beyond the validation-path coverage needed for this change.
- No additive `--case` + `--group` replay semantics.
- No remote artifact fetching; replay evidence remains local receipt metadata.

## Decisions

### 1. Policy group is authoritative

**Choice:** Load `determinism_replay_policy.groups`, find `id = "agent"`, and use that group's case list as the required agent receipt coverage.

**Rationale:** The replay group is already generated/reviewed policy. Making it authoritative removes hidden Rust drift and lets future group membership changes be policy-only when validation semantics do not change.

**Alternative:** Keep Rust constants synchronized with policy. Rejected because it preserves the drift this change is meant to remove.

### 2. Receipts expose group and expanded cases

**Choice:** Validation receipts include `required_replay_group` and `required_replay_cases`, where cases are policy-derived and sorted/stable. `replay_evidence` summaries include optional `replay_selected_groups`.

**Rationale:** Operators need to see both the shorthand group requirement and the expanded case proof.

### 3. Group evidence plus case coverage

**Choice:** If `replay_selected_groups` is present, require it to include `agent`; always require expanded `replay_selected_cases` to cover every policy-derived agent group case.

**Rationale:** Expanded cases keep old case-only evidence deterministic, while group evidence gives wrappers a stable policy shorthand and catches receipts generated by ad hoc case selections that happen to overlap accidentally.

### 4. Deterministic policy failures

**Choice:** Missing/malformed policy `agent` group produces a deterministic validation issue such as `replay_evidence.required_group_missing` rather than panicking or using fallback constants.

**Rationale:** Broken policy must be visible in machine-readable receipts.

## Risks / Trade-offs

- **Fixture churn**: Generated policy hash and agent fixture hashes may change. Regenerate only after confirming intentional schema/policy changes.
- **Sync drift**: The accepted supersession spec block has accumulated replay scenarios; inspect after sync to ensure prior scenarios remain.
- **Backwards compatibility**: Requiring `replay_selected_groups` could break older case-only receipts. This design requires group membership only when the field exists, while docs encourage wrappers to include it.
