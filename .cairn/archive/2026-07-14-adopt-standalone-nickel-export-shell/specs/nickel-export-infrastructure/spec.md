# Cairn Standalone Nickel Export Shell Specification

## Purpose

Adopt the immutable standalone external Nickel export shell while preserving Cairn lifecycle semantics, generated-policy ownership, gate authority, replay, and release-readiness decisions.

## ADDED Requirements

### Requirement: Standalone shell source is immutable

r[cairn.nickel_export_cutover.source] Cairn MUST pin `github.com/OnixResearch/nickel-export` revision `257fafc1c746f1faf156207043a4c826bfb16d49` and an exact supported Nickel evaluator cohort in release inputs.

#### Scenario: Exact source and evaluator are selected
- GIVEN dependency, flake, lock, and evaluator-version material match the declared cohort
- WHEN policy-export readiness runs
- THEN Cairn MAY invoke the standalone shell.

#### Scenario: Source or evaluator is mutable
- GIVEN a branch, mutable tag, workspace-relative release path, different revision, or unpinned evaluator is selected
- WHEN readiness runs
- THEN Cairn MUST reject the migration path.

### Requirement: External evaluation stays in a Cairn-owned shell

r[cairn.nickel_export_cutover.boundary] Cairn MUST keep repository-root selection, evaluator execution, dependency/contract selection, diagnostics, and generated destination writes in a Cairn-owned imperative shell and MUST pass exported values into Cairn semantic cores explicitly.

#### Scenario: Policy export succeeds
- GIVEN an authorized root, evaluator, request, dependency closure, contract/selector, and destination
- WHEN the wrapper invokes the standalone shell
- THEN Cairn MAY parse and validate the resulting exact bytes.

#### Scenario: Lifecycle core requests ambient I/O
- GIVEN a proposed migration makes a pure gate or policy core read files, execute Nickel, inspect environment state, or write destinations
- WHEN boundary validation runs
- THEN Cairn MUST reject the change.

### Requirement: Cairn lifecycle authority is retained

r[cairn.nickel_export_cutover.authority] Cairn MUST retain policy parsing, lifecycle-data semantics, gate interpretation, generated policy ownership, receipt/replay acceptance, and release-readiness decisions independently of standalone export admission.

#### Scenario: Export bytes are fresh
- GIVEN the standalone shell confirms exact generated bytes
- WHEN a lifecycle gate or readiness decision runs
- THEN every Cairn-owned semantic and policy check MUST still run.

#### Scenario: Export receipt is promoted into gate success
- GIVEN only a standalone receipt or manifest
- WHEN a caller requests gate success or release eligibility
- THEN Cairn MUST reject the unsupported promotion.

### Requirement: Migration dual-runs current export behavior

r[cairn.nickel_export_cutover.dual_run] Cairn MUST dual-run legacy and standalone paths over identical policy, lifecycle-data, dependency, evaluator, contract/selector, format, and destination inputs and MUST compare exact bytes, identities, diagnostics, and freshness outcomes.

#### Scenario: Valid exports agree
- GIVEN valid policy and lifecycle-data fixtures
- WHEN both paths run
- THEN policy bytes, lifecycle-data bytes, exact identities, and freshness decisions MUST agree.

#### Scenario: Invalid Nickel behavior differs
- GIVEN malformed, contract-invalid, stale, or tampered material
- WHEN both paths run
- THEN any success/failure, diagnostic-class, receipt, or destination-mutation difference MUST fail readiness.

### Requirement: Legacy commands provide fail-closed rollback

r[cairn.nickel_export_cutover.rollback] Cairn MUST keep current external Nickel commands authoritative through one complete positive and negative validation cycle and MUST block cutover on unexplained drift.

#### Scenario: Full export cohort agrees
- GIVEN policy, lifecycle-data, negative-diagnostic, and freshness fixtures pass under the pinned cohort
- WHEN the standalone wrapper becomes primary
- THEN Cairn MAY retain the legacy commands as a bounded rollback adapter.

#### Scenario: Drift appears
- GIVEN byte, identity, diagnostic, freshness, policy, or rejection drift
- WHEN rollback executes
- THEN legacy commands MUST remain authoritative and paired regression fixtures MUST be added before retry.

### Requirement: Migration validation preserves lifecycle non-claims

r[cairn.nickel_export_cutover.validation] Cairn MUST include positive policy/lifecycle export and freshness cases plus negative malformed-request, invalid-contract, stale-output, tamper, path-escape, symlink, evaluator-drift, and overclaim cases.

#### Scenario: Validation is complete
- GIVEN focused CLI/core tests, policy-export freshness, positive and negative fixtures, source-pin checks, Cairn lifecycle gates, and relevant Nix checks pass
- WHEN duplicate mechanics are reviewed
- THEN Cairn MAY remove only generic mechanics delegated to the standalone shell/core.

#### Scenario: Gate authority would move to shared evidence
- GIVEN no Cairn semantic or policy decision supports a requested gate result
- WHEN closeout evaluates standalone export evidence
- THEN the gate result MUST be rejected and the change MUST remain incomplete.
