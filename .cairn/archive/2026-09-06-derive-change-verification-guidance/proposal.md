# Derive change verification guidance

## Why

The content-bound trace index records declared requirement links, but it does not explain which checks a source change affects.
Developers must select a local check set and identify evidence that no longer applies.
Incorrect omission is more dangerous than a conservative extra check.

## What Changes

- Admit explicit before and after source identities, exact changed paths, current trace indexes, and a repository-owned check map.
- Derive affected requirements, declared checks, evidence refresh needs, and stable causal explanations in the pure core.
- Consume optional Octet structural evidence and Valence span identities through versioned adapters without promoting marker linkage to behavioral proof.
- Connect the result to unified readiness actions and the maintained check-evidence producer.
- Preserve the full required gate set and return conservative guidance when the supplied dependency map is incomplete.

The proposed command is `cairn verification-impact`. Its initial result is advisory check selection, not permission to omit a release gate.

## Impact

Maintenance owner: Cairn traceability and developer-loop maintainers.
Current consumer: Cairn source changes under its maintained developer-loop profile.
Immediate outcome: a developer sees why each focused check is relevant and which prior evidence requires refresh.
Durable contribution: a deterministic selection and explanation contract with explicit unknown coverage.

Hard local prerequisites are `unify-change-readiness-and-next-actions` and `produce-check-evidence-with-stack-adapters`.
The existing compiler-bound evidence and candidate-assurance plans keep their own scope. This change does not require their unmerged implementations.

Octet owns source-analysis meaning. Valence owns shared source and evidence identities.
Cairn owns the declared requirement-to-check policy and its conservative selection result.

## Repeatability evidence

Replay an exact source edit with affected and unaffected declared requirements.
Retain expected selections, explanation paths, and stale-evidence results.
Add deletion, rename, copied marker, missing link, cycle, stale index, macro, generated-source, feature, and target mismatch cases.
Use mutation controls to show that incomplete coverage never suppresses a required check.

## Out of Scope

- A compiler, source indexer, symbolic executor, or dependency scanner inside Cairn
- Automatic check execution or authority to shrink full repository gates
- Marker-based proofs of independence, test adequacy, or behavioral correctness
- Reuse of stale results solely because a changed file lacks a marker
- New Choregraph or Campaign scheduling dependencies
