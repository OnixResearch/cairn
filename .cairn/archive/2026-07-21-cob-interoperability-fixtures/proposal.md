## Why

Cairn's current COB compatibility suite creates and consumes histories through Cairn's adapter and the same in-process direct storage cohort. That proves the exercised implementation is internally consistent, but it does not detect every accidental dependency on Cairn's own encoder, ref writer, or reducer. A static fixture produced through the upstream Radicle Git storage adapter plus an independently implemented test consumer can expose those correlated failures without restoring Radicle runtime coupling.

## What Changes

- Add a provenance-bound static Git bundle generated by a separate reference producer using upstream `radicle::storage::git::Repository`, exact manually-authored Cairn action JSON, and pinned format-library versions.
- Verify Cairn can import the bundle, reproduce the declared root state, and append a signed delegate update without rewriting the reference-produced history.
- Add a test-only direct consumer with its own read-only ref discovery and Cairn action decoder, then verify it can evaluate Cairn-produced create and update histories.
- Add fail-closed checks for fixture hash drift, unsigned histories, incompatible manifest versions, and any reintroduction of Radicle runtime crates into the maintained product dependency graph.
- Extend the dedicated Nix compatibility gate to validate the typed Nickel provenance export and the two-way fixture suite.

## Impact

- **Files**: `fixtures/radicle-cob-interoperability`, `crates/cairn-radicle-cob` integration tests/dev dependencies, `flake.nix`, README/operator documentation, and native Cairn lifecycle artifacts.
- **Testing**: baseline and post-change adapter tests, fixture freshness and provenance checks, positive inward/outward interoperability, negative malformed fixture cases, dependency audit, formatting, workspace tests/Clippy, lifecycle/traceability, self-dogfood, and full flake validation.
