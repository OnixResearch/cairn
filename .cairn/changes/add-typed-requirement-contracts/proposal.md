# Add optional typed requirement contracts

## Why

Requirement identity, EARS vocabulary classification and structured Given/When/Then validation do not specify operands, finite quantification or the observable meaning of a proposition. Issue #5 and Roadmap #4 require explicit semantics before downstream derivations and kernel qualification can cite a contract.

## What Changes

- Add one opt-in finite semantics profile in native Nickel and a pure Rust normalization, typing, interpretation and review-declaration admission API.
- Link contracts directly to the existing exact content-bound native requirement row; keep Markdown authority and the existing registry.
- Author the five roadmap pilots with exact row bindings, observable projections, supported portions and named informal remainders.
- Expose read-only normalized meaning, independent correspondence declarations and example evaluations through `requirement-contract inspect`.
- Keep absent contracts visibly informal and every existing gate, receipt wire format and default unchanged.

## Impact

Current consumers are maintainers reviewing requirement meaning and the #6/#13 derivation/qualification workstreams. Cairn owns contract/policy meaning; external adapters own measured observations and existing evidence admission. No scheduler, automatic prose translation, proof producer or alternate registry is introduced.

Independent correspondence approval is deliberately not fabricated: the inventory ships proposals and no approvals. Final acceptance requires a separately retained independent review bound to the current identities and explicitly authorized reviewer policy.

## Out of Scope

Arithmetic, temporal operators, arbitrary program semantics, unbounded validity, source correctness, automatic authority transfer and changes to existing completion decisions are excluded. The claim-revision pilot names the stronger per-fact claim-root binding absent from the current WorkflowState representation as an informal remainder rather than inventing fields.

## Acceptance

All five contracts must normalize against native accepted rows. Positive/negative core and CLI cases must distinguish identity drift, duplicate/missing/non-pass rows, stale subjects, absent completion authority and revised epochs. Evaluation, correspondence declarations and proof evidence must remain distinct. Parent runs the actual generation, checks, independent review and lifecycle acceptance.
